# P0 — Foundation

## Objetivo

Preparar a estrutura do projeto e validar a comunicação entre frontend, backend e banco, partindo
do template base e adequando-o às decisões de arquitetura do Yoda.

## Entregas

- Estrutura do repositório (`apps/backend`, `apps/frontend`, `contracts/`, `docs/`).
- FastAPI configurado, com variáveis de ambiente, logging, CORS e envelope de erro.
- React + TypeScript configurado, consumindo o client gerado do contrato.
- PostgreSQL local, SQLAlchemy 2 assíncrono e Alembic.
- Docker Compose com banco, backend e frontend.
- Estrutura modular por domínio: módulos `users`, `conversations`, `assistant` e `context` criados
  apenas com o `__init__.py`, ainda sem funcionalidades.
- Regras de dependência entre módulos e entre arquivos de um módulo (`router` → `service` →
  `repository` → `models`) verificadas pelo `import-linter`.
- Contrato OpenAPI como fonte da verdade, verificado por teste.
- Health check que verifica o banco.
- Nome do projeto aplicado (`yoda`; `Yoda` na interface).

O módulo `example` permanece até o primeiro endpoint real do P1, como prova de comunicação
frontend ↔ backend ↔ banco e como referência de estrutura de módulo.

## Fora do escopo

Autenticação, conversas, mensagens, integração com a OpenAI, streaming e interface de chat (P1).

## Critério de conclusão

Frontend, backend e banco executam localmente com `make up` e se comunicam: `/health` responde
`200` com o banco disponível e `503` sem ele, e a tela do `example` lista e cria registros
persistidos no Postgres. Lint, testes, verificação de contrato e build passam.
